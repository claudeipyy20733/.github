<p>账单到手时，多数人只看到总价涨了一截，说不清是哪一项在涨。住宅代理的成本结构其实很线性：出口数量、并发上限、流量消耗、失败重试，四项各自计价又互相影响。鉴权方式选错会抬高运维成本，超时设得保守会让有效请求变少，重试设得激进会把一次失败放大成三次计费。下面把这四项摊开算，给出参数建议和对应的成本影响方向。</p>

<h2>一、先看账单里真正在涨的四项</h2>
<p>第一项是出口数量，按条计费，与是否使用无关；第二项是并发上限，通常分档计价，超过档位要么排队要么加钱；第三项是流量，按 GB 计，附件和图片是主要消耗方；第四项是失败重试带来的重复消耗，它不单独出现在账单上，但会推高前三项的实际用量。</p>
<p>四项里最容易被忽略的是第四项。一次超时后自动重试三次，如果三次都失败，流量已经消耗了三份，成功率却是零。账单上看不出异常，因为单价没变，只是用量变多了。</p>

<h2>二、鉴权方式决定了多少隐性成本</h2>
<p>白名单、账号口令、令牌（Token），三种方式的显性价格差别不大，隐性成本差别明显。白名单最省事但最脆弱，口令最灵活但凭证管理麻烦，令牌介于两者之间，适合多环境。</p>

<h3>切换成本比单价更值得算</h3>
<p>白名单方案每次本地地址变动都要改一次配置，如果一个月变五次，每次十分钟，一年就是十小时。把这十小时折算进成本，白名单未必比令牌便宜。评估时应把「每年需要人工干预的次数」乘以单次处理时间，作为隐性成本的一项。</p>

<h2>三、并发数怎么换算成月费</h2>
<p>并发是分档的，常见档位是十、五十、一百、五百。选档的关键不是平均并发，而是峰值并发。平均并发十、峰值五十的情况下，按十档买会天天排队，按五十档买则有一半时间闲置。</p>
<h3>峰值与均值通常差两到四倍</h3>
<p>浏览器页面的并发特征是突发式的：打开页面瞬间拉起十几条连接，几秒后回落到两三条。这种波形让均值看起来很低的，峰值却很高。取一周数据，统计每分钟的连接数峰值，取第九十五百分位作为选档依据，比取平均值更贴近实际。</p>
<p>如果峰值只是偶发，可以考虑「基础档 + 排队容忍」的策略：超出的请求排队而不是加档，代价是高峰期响应变慢。是否接受，取决于业务对延迟的敏感度。</p>

<h2>四、超时与重试是成本的放大器</h2>
<p>超时设得太长，失败请求会占着连接不放，等效于降低并发；设得太短，正常但稍慢的请求被误判失败，触发重试。两个方向都在推高成本，只是一个体现为排队，一个体现为流量翻倍。</p>

<h3>重试次数与退避要成对配置</h3>
<p>只调重试次数不配退避，等于在目标已经限流时连续敲门，效果是失败率更高、消耗更多。建议第一次重试等一秒，第二次等两秒，第三次等四秒，同时把总重试上限控制在两次。经验上，两次重试能覆盖大部分瞬时故障，第三次之后成功率提升很有限。</p>
<p>另外要区分「可重试」和「不可重试」的错误。连接超时、502、503 可以重试；401、403、404 重试没有意义，只会浪费流量。在代码里按状态码分流，比统一重试省下不少。</p>

<h2>五、把一个月拆成四项来算</h2>
<p>以单人使用、日均两小时、含少量附件上传为例，四项的占比大致是：出口数量占四成，并发档位占三成，流量占两成，重试溢出占一成。如果附件多，流量占比会上升到四成以上，这时候更该优化的是压缩与缓存，而不是换更贵的套餐。</p>

<h2>常见问答</h2>
<h3>并发档位买大了能退吗？</h3>
<p>答：多数按月结算的服务商支持次月调整，当月不退。所以首次采购建议选小一档，观察一周的排队情况再升级，比一开始买大档更省钱。</p>
<h3>流量超了怎么计费？</h3>
<p>答：常见两种：按超出部分单价计费，或直接限速至某个阈值。前者要留意单价通常高于套餐内均价，后者要看限速后是否还能完成正常请求。</p>
<h3>重试是不是越多越稳？</h3>
<p>答：不是。重试只能覆盖瞬时故障，对持续性故障无效，反而会放大消耗。稳定性的关键在出口质量和超时设置，重试只是兜底。</p>
<h3>小规模使用选按流量还是按月？</h3>
<p>答：日均请求少于几百次、流量在几 GB 以内的，按流量通常更省；每天长时间在线、流量稳定的，按月更划算。可以先各用一个月对比账单。</p>
